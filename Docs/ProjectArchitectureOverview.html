JBRogLike 프로젝트 아키텍처 및 기능 소개

JBRogLike는 Unity 2D Tilemap 기반의 탑다운 로그라이트 프로젝트입니다. 고정 마을과 절차 생성 던전을 하나의 Main 씬 안에서 전환하며, 방 단위 전투, Fog of War, 직접 렌더링 미니맵, ScriptableObject 기반 전투 데이터를 중심으로 구성됩니다.

Engine: Unity 2D Language: C# Scene: Main.unity Map: Tilemap + Procedural Grid Updated: 2026-05-18

1. 프로젝트 개요

핵심 게임 루프

플레이어는 마을에서 시작해 던전 포탈로 입장하고, 절차 생성된 방과 통로를 탐험합니다. 방 진입 시 적이 스폰되고, 적 처치 후 문이 열리며, 계단을 통해 다음 층으로 진행합니다.

월드 구성

Main 씬 안에 TownRoot와 DungeonRoot가 공존합니다. 마을은 고정 Tilemap, 던전은 DungeonManager.Generate()로 생성되는 런타임 Tilemap입니다.

전투 구성

플레이어는 기본 공격, 4개 스킬 슬롯, 대시, 투사체 스킬을 사용합니다. 적은 Contact/Ranged 행동과 Rush/Jump 같은 특수 공격을 가질 수 있습니다.

시야와 정보 표시

FogOfWarController가 탐험/가시 셀을 관리하고, MinimapController가 카메라 RenderTexture 없이 Texture2D/Tilemap 데이터를 직접 그립니다.

2. 전체 아키텍처

구조는 MonoBehaviour가 런타임 흐름을 조율하고, 순수 C# 서비스와 ScriptableObject 데이터가 세부 규칙을 담당하는 형태입니다. 대부분의 시스템은 Inspector 참조, Singleton성 active reference, Registry, EventChannel로 연결됩니다.

계층 주요 책임 대표 타입
Application / Orchestration 게임 흐름, 씬 루트 전환, 던전 생성, 플레이어 입력/상태 조율 DungeonManager, TownDungeonTransitionManager, PlayerController, PlayerCombatController
Domain / Services 던전 생성 알고리즘, 좌표 변환, 스폰 위치 계산, 공격 패턴, 스킬 실행 로직 DungeonGenerator, DungeonQueryService, SpawnPositionService, AttackPattern, SkillExecutor
Data 무기, 스킬, 적, 텔레포트 목적지, 던전 셀 데이터 WeaponData, SkillData, EnemyData, TeleportDestinationDatabase, DungeonData
Presentation Tilemap 표시, UI, 미니맵, 체력바, 피격/무적 피드백 DungeonTilemapRenderer, MinimapController, SkillUIManager, EnemyHealthBar
Messaging / Registry 직접 참조를 줄이는 이벤트/등록 기반 연결 DungeonEventChannel, CombatEventChannel, TeleportDestinationRegistry, LocationMinimapRegistry 
입력/플레이어
  -> PlayerController / PlayerCombatController
  -> DungeonManager, Combat Services, ProjectilePool
  -> DungeonEventChannel / CombatEventChannel
  -> Door, RoomSpawner, UI, Fog, Minimap

3. 씬과 루트 구조

현재 전환 구조는 Main 씬 단일 운영을 전제로 합니다. Player, Camera, Canvas, Manager류는 공통 루트에 두고, 지역별 Tilemap/Collider/Portal만 TownRoot와 DungeonRoot 아래에 둡니다. 

Main
├─ TownRoot
│  ├─ Town Tilemap Grid
│  ├─ TownSpawnPoint + TeleportDestinationPoint("town_start")
│  ├─ TownReturnSpawnPoint + TeleportDestinationPoint("town_return")
│  └─ DungeonEntrancePortal + TeleportService("dungeon_entrance")
├─ DungeonRoot
│  ├─ Dungeon Tilemap Grid
│  └─ DungeonEntrancePoint + TeleportDestinationPoint("dungeon_entrance")
├─ Player
├─ Main Camera
├─ Canvas / UI
└─ Managers

루트 활성화는 TownDungeonTransitionManager가 담당합니다. 현재 위치 타입에 따라 Town/Dungeon 오브젝트를 켜고 끄며, 미니맵은 지역에 맞는 소스를 사용합니다.

4. 던전 생성/층 이동

DungeonManager는 던전 생애주기 Facade입니다. 실제 생성 알고리즘과 좌표/스폰/전환 보조 로직은 전담 서비스로 분리되어 있습니다.

1. 설정 구성 - 맵 크기, BSP 깊이, 방 크기, seed/floor 값을 DungeonSettings로 구성합니다.
2. 절차 생성 - DungeonGenerator가 BSP 기반 방 배치와 MST/추가 연결 통로를 생성합니다.
3. 데이터화 - grid와 room rect를 DungeonData, RoomInfo, RoomRegistry로 변환합니다.
4. 스폰 위치 계산 - SpawnPositionService가 시작 방 기준 위치를 계산하고 캐시합니다.
5. Tilemap 렌더링 - DungeonTilemapRenderer가 바닥/벽/문/계단을 Tilemap에 배치합니다.
6. 층 이동 - FloorTransitionService와 로딩 화면을 통해 생성 비용을 흡수하고 이벤트를 발행합니다.
타입설명
ROOM방 바닥. 일반 방, 스폰 방, 몬스터 방, 계단 방 등으로 분류됩니다.
CORRIDOR방 사이 연결 통로입니다.
DOOR_CLOSED전투 중 통로를 막는 문입니다. 방 클리어 후 열립니다.
STAIR_UP다음 층 이동 트리거입니다.

5. 마을/던전 전환

TownDungeonTransitionManager가 현재 GameLocationType을 관리합니다. 시작 시 town_start 목적지로 이동하며, 던전 입장과 귀환도 동일한 텔레포트 요청 경로를 탑니다.

전환처리
Town -> Dungeon DungeonRoot 활성화, TownRoot 비활성화, 새 run 생성, floor 1 초기화, Fog 초기화, RoomSpawner 상태 reset, Player를 던전 시작 위치에 배치
Dungeon -> Town Projectile release, active enemy pool 반환, RoomSpawner runtime 상태 clear, TownRoot 활성화, Player를 town_return 위치에 배치
동일 LocationType 이동 root 전환 없이 목적지 point 위치로 Player만 이동

6. 텔레포트 목적지 시스템

목적지는 개별 ScriptableObject가 아니라 하나의 TeleportDestinationDatabase에 여러 TeleportLocationData를 등록하는 방식입니다. 씬 안의 실제 위치는 TeleportDestinationPoint가 ID로 registry에 등록합니다. 

TeleportService("dungeon_entrance")
  -> TownDungeonTransitionManager.TeleportPlayer(player, "dungeon_entrance")
  -> TeleportDestinationDatabase.TryGetLocation(id)
  -> GameLocationType 비교
  -> TeleportDestinationRegistry.TryGetPoint(id)
  -> 위치 이동 또는 던전 run 생성
확장 방식: 새 장소를 추가할 때는 Database에 ID/이름/설명/LocationType을 추가하고, 씬에 같은 ID를 가진 TeleportDestinationPoint와 TeleportService를 배치하면 됩니다.

7. 플레이어 시스템

PlayerController는 이동, 던전 좌표 변환, 방 진입, 계단 상호작용을 담당합니다. 던전에서는 DungeonManager.IsFootprintWalkable을 사용하고, 마을에서는 일반 movement blocker 중심으로 이동 가능 여부를 판단합니다.

컴포넌트책임
PlayerInputReader입력 값을 한 곳에서 읽어 이동/공격/스킬 시스템에 제공합니다.
PlayerController이동, 충돌 검사, grid/world 변환, 방 진입 및 층 이동 감지를 담당합니다.
PlayerCombatControllerHP/MP, 기본 공격, 스킬, 피격, 상태 이상, 전투 이벤트를 관리합니다.
PlayerDashController대시 이동, 대시 중 충돌/피해/무적 처리를 담당합니다.
PlayerAnimationController이동 방향과 마지막 방향을 Animator에 반영합니다.

8. 전투/스킬/투사체

전투는 데이터 주도형입니다. WeaponData가 기본 공격과 스킬 목록을 제공하고, SkillData가 실행 방식, 비용, 쿨다운, 공격 범위, 투사체, 대시 정보를 정의합니다.

공격 판정

AttackPattern이 Cross, Line, Cone 등 타일 기반 범위를 계산하고, AttackExecutor가 대상 탐지와 피해 적용을 수행합니다.

스킬 실행

SkillExecutor는 SkillExecutionType에 따라 InstantArea, Projectile, Dash 흐름을 분기합니다.

투사체

ProjectileFireService가 Single/Burst/Spread/Circle 패턴을 만들고, ProjectilePool이 생성/반환 비용을 줄입니다.

상태 이상

적 공격은 knockback, slow, stun을 줄 수 있고, 플레이어 UI는 PlayerStatusEffectUI로 상태를 표시합니다.

9. 적 AI와 스폰

적은 EnemyData로 행동/스탯/스폰 비용을 정의하고, EnemyPoolManager에서 재사용됩니다. AI는 EnemyBrain 기반 FSM이며, 이동/타겟/행동 책임이 Handler로 나뉩니다.

시스템설명
RoomSpawner방 최초 진입 이벤트를 받고, 예산 기반으로 적 후보를 선택해 안전한 타일에 배치합니다.
EnemyBrainIdle, Chase, Attack 상태 전환을 관리합니다. 보스/특수 적은 상태 확장 가능 구조입니다.
MovementHandlerA* 경로 이동, separation, ranged movement를 담당합니다.
ActionHandlerContact/Ranged 공격과 Rush/Jump 특수 공격 쿨다운/타이밍을 담당합니다.
EnemyControllerHP, 피해, 사망, 피격 효과, 상태 이상을 관리합니다.

방 전투 중 적이 남아 있으면 DungeonManager.CloseCurrentRoomDoors가 문을 닫고, 모든 적이 사망하면 OpenCurrentRoomDoors로 문을 다시 엽니다.

10. Fog of War

FogOfWarController는 던전 셀별 explored/visible 상태를 관리합니다. 플레이어 위치가 바뀌거나 방/문 상태가 변하면 시야를 다시 계산하고, 변경된 셀만 Tilemap에 반영합니다.

  • IsExploredCell(Vector2Int)와 IsVisibleCell(Vector2Int)로 다른 UI 시스템이 읽기 전용 조회를 할 수 있습니다.
  • 현재 방 reveal, 방 경계 reveal, 벽/문 시야 차단 옵션을 Inspector에서 조절합니다.
  • VisibilityChanged 이벤트로 미니맵 갱신 타이밍을 제공합니다.

11. 미니맵/UI

미니맵은 추가 Camera나 RenderTexture를 쓰지 않습니다. 던전 모드에서는 DungeonData와 Fog 상태를 기준으로 Texture2D를 직접 생성하고, 마을 같은 고정 지역은 TilemapMinimapSource를 통해 Tilemap 기반 미니맵을 그립니다.

UI역할
MinimapController던전/타일맵 소스를 전환하고, Texture2D와 PlayerMarker 위치를 갱신합니다.
TilemapMinimapSource마을 등 고정 Tilemap의 ground/wall 정보를 미니맵 source로 등록합니다.
SkillUIManager스킬 슬롯 아이콘, 쿨다운, 사용 가능 상태를 표시합니다.
PlayerStatusBarUIHP/MP 상태를 CombatEventChannel 기반으로 갱신합니다.
GameOverFlowController플레이어 사망 후 게임오버 UI 흐름을 제어합니다.

12. 데이터 에셋

밸런싱 가능한 값은 최대한 ScriptableObject로 분리되어 있습니다. 코드 변경 없이 적, 무기, 스킬, 텔레포트 목적지를 추가/조정할 수 있는 구조입니다.

데이터포함 정보
WeaponData무기 이름, 아이콘, 기본 공격, 장착 스킬 목록
SkillDataMP, 쿨다운, cast/recovery, 범위, 투사체, 대시, 상태 이상
EnemyData스탯, 스폰 비용, 행동 타입, 원거리/근접 공격, 특수 공격, 보상
TeleportDestinationDatabase목적지 ID, 표시 이름, 설명, LocationType, 미니맵 location ID
DungeonEventChannel방 진입, 층 변경, 문 열림/닫힘 이벤트
CombatEventChannelHP/MP 변경, 스킬 사용, 적 사망, 플레이어 사망 이벤트

13. 성능 전략

  • 풀링: 투사체와 적은 Pool을 통해 재사용하고, 층 이동/지역 이동 때 활성 오브젝트를 회수합니다.
  • 이벤트 기반: 방 진입, 층 이동, Fog 변경 시점에만 관련 시스템을 갱신합니다.
  • 캐싱: DungeonManager는 스폰 위치, 서비스 인스턴스, query service를 캐시합니다.
  • 미니맵 최적화: 전체 texture scan은 Fog/층 변경 등 필요한 시점에만 수행하고, 매 프레임은 player marker 이동 감지만 합니다.
  • Tilemap chunking: 층 전환 시 Tilemap 배치를 여러 row chunk로 나눠 프레임 hitch를 줄일 수 있습니다.
  • Registry: 텔레포트/미니맵 source는 Find 계열 반복 탐색 대신 등록/해제 방식으로 조회합니다.

14. 확장 포인트

새 지역 추가

GameLocationType 확장, Database location 추가, 새 Root/Tilemap/TeleportDestinationPoint 배치로 시작할 수 있습니다.

새 적 추가

EnemyData asset을 만들고 RoomSpawner enemy table에 등록합니다. 필요하면 EnemyBrain 상속으로 특수 상태를 추가합니다.

새 스킬 추가

SkillData를 만들고 execution type을 선택합니다. 범위/투사체/대시 값은 Inspector에서 조정합니다.

새 미니맵 소스

고정 장소는 TilemapMinimapSource를 배치하고 location ID를 Database의 minimapLocationId와 맞춥니다.
